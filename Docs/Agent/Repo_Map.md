# Repo Map (full)

Moved from `CLAUDE.md`; read when the task touches this area.

- `README.md`, `DOCUMENTATION.md` - high-level intro, controls, feature list, and planned work.
- `Docs/TODO.md` - current editor issues.
- `Docs/Importing Structure.md` - best summary of the asset/content pipeline.
- `Engine/Program.cs` - standalone engine entry point.
- `Engine/Engine.cs` - MonoGame `Game` subclass; creates graphics, physics, `ScreenManager`, and `EditorBridge`.
- `Engine/Logic/ScreenManager.cs` - central coordinator for load/init/update/draw across renderer, scene logic, GUI, editor logic, debug screen (stats), intro video, and script UI (`GameUI`).
- `Engine/Logic/MainSceneLogic.cs` - owns the live scene lists: entities, decals, lights, debug entities, camera, environment sample, and editor-side add/delete helpers.
- `Engine/Logic/EditorLogic.cs` - in-engine editor mode, selection, gizmos, delete/copy behavior.
- `Engine/Logic/GameFlow.cs` - script API for the scene list: queued `LoadScene(index/name)` (one frame), `LoadSceneAsync` (background load + loading screen, returns a `SceneLoadOperation`), `Quit`, `EscapeQuits`, `PlayStopped`.
- `Engine/Logic/Cutscene.cs` + `Cutscenes.cs` - cutscenes (`Docs/markdown/Cutscenes.md`): `.cutscene` JSON in `Content/Cutscenes` (camera keys: time/position/yaw/pitch/FOV/Cut/Ease, Catmull-Rom path; events: Subtitle/FadeOut/FadeIn/Sound/Message, saved by name); static player `Cutscenes.Play/Skip/Stop/IsPlaying/Finished/EventFired` drives the game camera after the scripts (Play only) and draws letterbox/fade/subtitle in `ScreenManager.Draw`; Edit-mode `Preview`/`CaptureEditorCamera` for Anvil > Window > **Cutscenes**, a panel docked above Console/Assets, also opened by double-clicking a `.cutscene` asset (`AssetKind.Cutscene`) (`Editor/Anvil/Views/CutsceneEditorView.axaml`, `ViewModels/CutscenesViewModel.cs`, `Controls/CutsceneTimeline.cs`). No-code: **Cutscene Trigger** script (`Content/Scripts/CutsceneTriggerScript.cs`). Checks: `Tests/Components/CutsceneChecks.cs` (`--cutscenes`).
- `Engine/Logic/SceneLoadOperation.cs` + `LoadingScreen.cs` - scene loads: worker-thread `SceneSerialization.ReadFile`, `SceneBuilder` steps within `GameFlow.LoadBudgetMs` per frame, swap (`MainSceneLogic.ActivateLoadedScene`), 3 finishing frames; real `Progress`, `AllowSceneActivation`, `Cancel`, timings (`LongestFrameMs`). The loading screen is an engine overlay layer (`GameUI.OpenOverlay`, `Content/UI/LoadingScreen.xml`). Sample: `Content/Scenes/SceneLoadingTest.obsc` <-> `SceneLoadingArena.obsc` (`Content/Scripts/SceneLoadingTestScript.cs`); see `Docs/markdown/Scenes_and_Game_Flow.md`.
- `Engine/Logic/GameInput.cs` - script input merging keyboard (native + Anvil-forwarded), mouse and gamepads; menu navigation with key repeat. Ends by updating the input actions.
- `Engine/Logic/InputActions.cs` + `InputActionList.cs` + `InputControls.cs` + `Engine/Scripting/ScriptBehaviour.Input.cs` - input actions: named Button/Axis/Vector2 actions (`Content/System/InputActions.json`, defaults Move/Look/Jump/Sprint/Crouch/Interact/Attack/Previous/Next/Pause) bound to control paths (`Keyboard/Space`, `Mouse/Delta`, `GamePad/LeftStick`...), simple or composite (Up/Down/Left/Right, Negative/Positive) with Modifier/Scale/Per Second/Invert; the strongest binding wins. Scripts: `WasActionPressed("Jump")`, `IsActionDown`, `WasActionReleased`, `GetAxis`, `GetVector("Move")`, `BindingText`, `GetAction` (`WasPressedWithin`/`ConsumePress`, `Rebind`, `Enabled`); `InputActions.ListenForControl/SaveBindings/LoadBindings`. Anvil: Window > Input Actions (`InputActionsViewModel`, `Views/InputActionsWindow.axaml`, Listen via `Services/KeyMap.cs`); Save reloads the running engine (`RequestReload`), Stop restores the project's (`Load`). Sample: `Content/Scripts/CollisionTestPlayerScript.cs`; see `Docs/markdown/Input_Actions.md`.
- `Engine/Logic/GameUI.cs` - Vista layers opened by scripts (menus/HUDs), scaled from a 1080p canvas, hot-reloaded from source Content.
- `Engine/Recources/SceneList.cs` - build order of scenes (`Content/System/SceneList.json`); index 0 boots the standalone game.
- `Engine/Renderer/Renderer.cs` - main render pipeline and render target ownership.
- `Engine/Renderer/RenderModules/` - individual rendering modules: G-buffer, deferred lighting, froxels, shadows, TAA, bloom, decals, SDFs, forward pass, editor outlines.
- `Engine/Entities/` - scene object types like `BasicEntity`, `Camera`, lights, decals, transformable base type. `SpotLight` derives from `PointLight` and lives in the scene's `PointLights` list; every point light shader multiplies by a spot cone (point lights pass outer cosine -2).
- `Engine/Components/` - gameobject components (`GameComponent`, `ComponentRegistry`, Material, Physics, Audio, Animator). See "Adding a Gameobject Component".
- `Engine/Animation/` - skeletal animation: `SkinningData` (skeleton + clips from `Model.Tag`), `AnimationPlayer` (sampling, retargeting by bone name, `BlendFrom` for crossfades), `SkinnedMeshInstance` (CPU skinning into per-entity vertex buffers that `MeshMaterialLibrary` draws via `TransformMatrix.Skin`). `AnimatorComponent.Actions` are named clips scripts play (`Animator.Play("Walk")`, `PlayOnce`, `Stop`, `Pause`, `ActionFinished`); sample: `Y Bot - Actions` in `Content/Scenes/AnimationTest.obsc` + `Content/Scripts/AnimatorActionsScript.cs`. Posed bones: `BasicEntity.BonePose` (`BonePose.cs`, saved by bone name, applied via `AnimationPlayer.Overrides`, skinned in Edit mode by `BonePose.UpdateAll`); Anvil lists an **Armature** + bone tree under each skinned gameobject (`EditorObjectSnapshot.Bones`, `BridgeReconciler.ApplyBones`), and selecting a bone selects an `Engine/Entities/BoneObject.cs` proxy (negative IDs) that the rotation gizmo/Inspector turn.

- `Engine/Physics/RagdollRig.cs` + `Ragdoll.cs` + `Engine/Components/RagdollComponent.cs` - ragdolls for skinned gameobjects: `RagdollRig` splits a model into parts (convex hulls of each main bone's vertices) and shapes the joints for the component's **Skeleton** (`RagdollSkeletonType`, saved by name: Auto/Humanoid = limits from bone names, knee/elbow hinges; Quadruped = legs found as downward chains reaching the ground, shoulder/hip cones + elbow/wrist/knee/hock hinges, tail chains; Generic = cones from the bone tree for snakes/spiders/tentacles; hinges bend towards `Part.Flex`), `Ragdoll` owns the BEPU bodies/joints (kinematic while animated, dynamic when limp; `ScenePhysics.CreateRagdoll` drives it around each step), the component handles Play, impacts and the skin. Bodies of one gameobject share a collision group (`PhysicsSystem.SetCollisionGroup`). Sample: the ragdoll row of `Content/Scenes/AnimationTest.obsc` (Y/X Bots and two `Assets.Wolf` quadrupeds; the Wolf is generated by `Content/GameObjects/Wolf/Source/generate_wolf.py` in headless Blender) + `Content/Scripts/RagdollTestScript.cs`; see `Docs/markdown/Ragdoll_Physics.md`.
- `Engine/Physics/GlassFracture.cs` + `GlassShatter.cs` + `Engine/Components/BreakableGlassComponent.cs` - breakable glass like Half-Life: Alyx's `func_shatterglass` (type id `breakable-glass`; research in `Docs/Research/BreakableGlass/README.md`): the thinnest local side of the model is the pane normal; the first hit cracks it into Valve's jittered-grid Voronoi panels (`GlassFracture.CrackPane`, Crack Size 0.381 m), hits split the panels they touch into radial pieces (`ImpactSites`), the hole's pieces and panels not joined to the border (`Supported`) fall as dynamic convex bodies with their own mesh parts (15 s, max 150 scene-wide). Panels in the frame are one mesh part + a static convex each owned by the gameobject (`ScenePhysics.AddOwnedStatic`), and `Reconcile` drops the gameobject's collider once cracked (`BasicEntity.Glass`). Contacts reach `GlassShatter.Hit` in `UpdateTouches`; hits apply after it; a body that breaks through gets its speed back. Cracked glass draws with a damaged material (faces) and an edge material (cracked sides + a chipped bevel, UVs along the edge every 0.508 m): `.mat` assets or the built-in `GlassTextures`. Scripts: `Shatter(point/hit, direction, GlassStress, speed, radius)`, `Restore`, `Shattered`. Sample: the window station of `Content/Scenes/CollisionTest.obsc` (Attack shoots, F throws); see `Docs/markdown/Breakable_Glass.md`.
- `Engine/Physics/MeshFracture.cs` + `FractureShatter.cs` + `Engine/Components/BreakableComponent.cs` - breakables (type id `breakable`): any closed model breaks into 3D Voronoi pieces during Play (vases, pots, zombie heads). Play start reads the model's buffers (`FractureShatter.ReadMesh`; the bounding box without a model) and fractures on a worker thread (`MeshFracture.SurfaceSites` + `Fracture`: bisector-plane clipping, cuts capped by `AddCap` loops with holes, wound like the mesh = sign of its volume). A hit above Impact Speed/Momentum (reduced mass, own mass against immovable things; via `UpdateTouches` like glass) or `Break(...)` detaches the collider, hides the model and spawns dynamic convex piece bodies with one mesh part per material (`BasicEntity.PartMaterial`; cut faces = `InteriorColor`), max 200 scene-wide. `Effect` Dust/Blood = `MainSceneLogic.BreakBursts` (`Engine/Particles/BreakBursts.cs`, engine-owned particles). `FollowObject`/`FollowBone` ride on a bone (offset from the editor's rest pose); on break `CollapseBone` adds it to the followed gameobject's `CollapsedBones` (`Engine/Animation/BoneCollapse.cs`, applied by Animator/Ragdoll/BonePose skinning) and `RagdollOnBreak` activates its Ragdoll. Built-in `Assets.Vase` / `Assets.Head` (`Content/GameObjects/Vase|Head/Source/generate_*.cs`); Anvil GameObject > Effects > Breakable Vase. Sample: `Content/Scenes/BreakableTest.obsc` (CollisionTest player: Attack shoots Breakables up to 40 m); see `Docs/markdown/Breakables.md`.
- `Engine/Physics/LiquidSlosh.cs` + `LiquidVolume.cs` + `Engine/Components/LiquidComponent.cs` - liquid in bottles like Half-Life: Alyx (type id `liquid`; research in `Docs/Research/BottleLiquid/README.md`): no fluid sim, a plane the container's own Forward Shaded glass shows liquid below. `LiquidSlosh` ports Alyx's server think in Source units (every 0.1 s `pow(Δv + Δω, 0.6)` feeds agitation/foam peaks that decay linearly over 20/30 s; down = normalize(gravity − velocity) eased 20 % per 0.1 s; velocities from the transform, so the gizmo sloshes it too) and the shader's per-instance wobble (~21 rad/s) + level; `LiquidVolume` measures the fill tables (upright/side/upside down × 9 fills) from the closed mesh by plane clipping (Alyx: 3 hand-typed `g_vLiquidLevel*MinMidMax`). `LiquidComponent.UpdateAll` runs every frame from `MainSceneLogic.Update` (Edit and Play, held while paused) → `TransformMatrix.Liquid`/`LiquidLook`; `Forward.fx` `UseLiquid` (Alyx ripples, meniscus, water line, foam, bubbles); `MeshMaterialLibrary` draws liquid containers back faces first (the liquid's top). Scripts: `Fill`, `Agitate`, `Settle`, `Agitation`. Built-in `Assets.Bottle` (`Content/GameObjects/Bottle/`, `Source/generate_bottle.cs`; Anvil GameObject > Effects > Liquid Bottle). Sample: `Content/Scenes/LiquidTest.obsc` + `Content/Scripts/LiquidTestScript.cs`; see `Docs/markdown/Bottle_Liquid.md`.
- `Engine/Physics/Cloth.cs` + `ClothCollider.cs` + `ClothMeshInstance.cs` + `Engine/Components/ClothComponent.cs` - cloth: a mesh's welded vertices simulated as XPBD particles (10 substeps, stretch/bend constraints, air drag + scene wind, `ClothPinMode` pins following the gameobject) that collide one-way with the BEPU colliders `ScenePhysics.CollectClothColliders` gathers (hulls/boxes as planes, static meshes as two-sided triangles, triggers skipped). `ClothMeshInstance` writes the particles into per-gameobject vertex buffers drawn via `TransformMatrix.Cloth` (like `Skin`). Mesh: `Assets.Cloth` (`Content/GameObjects/Cloth/cloth.obj`, double-sided 24x24 plane in X/Z). Sample: the Curtain/Drape Sheet station of `Content/Scenes/CollisionTest.obsc` + `Content/Scripts/ClothReporterScript.cs`; see `Docs/markdown/Cloth.md`.
- `Engine/AI/NavGrid.cs` + `Navigation.cs` + `Engine/Components/NpcComponent.cs` - NPCs: `NavGrid` is a 0.25 m height field cast down through the **static** colliders only (`ScenePhysics.RaycastStatic`; dynamic bodies are see-through), eroded by agent radius + half a cell (walls, ledges, holes), with step/slope limits, regions and A* + string pulling (`FindPath`, `TryRandomPoint`, `TryFleePoint`). `Navigation.For` caches one grid per physics scene and agent size, rebuilding (at most every 30 frames) when a static moves; `Navigation.Invalidate()` forces it. `NpcComponent` (type id `npc`) = idle (`NpcIdleBehaviour` Stand/Wander/Patrol by gameobject names) + sight (range, FOV around +Y, hearing range, line-of-sight rays every 0.1 s) + reaction (`NpcReaction` Chase+attack impulse/Follow/Flee/Watch) + search after losing the target; moves a Dynamic body by velocity (or the gameobject directly without one). Script hooks `OnTargetSpotted/OnTargetLost/OnNpcStateChanged/OnNpcAttack`, API `MoveTo/Investigate/Alert/Calm/CanSee`, `ScriptBehaviour.FindPath`. Sample: `Content/Scenes/NpcTest.obsc` (`NpcTestPlayerScript`, `NpcReporterScript`, `UI/NpcTest`); see `Docs/markdown/NPC_Navigation.md`.
- `Engine/Components/LodComponent.cs` - level of detail (type id `lod`): `Levels` (model key + camera distance) and `CullDistance`. `BasicEntity.RegisterInLibrary` registers the model as level 0 and each LOD model as level 1..n (`MeshLibrary.LodLevels`); `Renderer.Draw` calls `MeshMaterialLibrary.SelectLevelsOfDetail` before the shadow maps, which sets `TransformMatrix.LodLevel` (-1 = culled) and `Draw` skips other levels. Visual only (physics/SDF/bounds use the own model); works in edit mode and Play. Sample: `Content/Scenes/LodTest.obsc`; see `Docs/markdown/Level_of_Detail.md`.
- `Engine/Components/FoliageWindComponent.cs` + `Engine/Renderer/Helper/FoliageWind.cs` + `Content/Shaders/Common/FoliageWind.fx` - trees swaying in the scene wind (type id `foliage-wind`, Edit and Play, held while paused): `MainSceneLogic.Update` calls `FoliageWindComponent.UpdateAll` (wind clock, strength = `WeatherProfile.Wind` m/s / 6 after Wind Scale/Min Wind, height from the model bounds) which puts a `FoliageWind` on `TransformMatrix.Wind` and flags `HasChanged` every frame (shadows redraw). The vertex shaders of the G-buffer, `ShadowMap.fx` and `IdRender.fx` include `FoliageWind.fx` (trunk bend ~height², branch sway by distance from the trunk axis, leaf flutter only for `MaterialTypes.Foliage` = 8, fading to the card's stem at texture v = 1, per-card phase from `floor(u)`); `MeshMaterialLibrary.Draw` sets it per material (`SetMaterial`) and instance (`SetInstance`) through `IFoliageWindModule`/`Shaders.IdRenderEffectWind`. Foliage pixels get sunlight through their back (`FoliageTransmission` in `DeferredDirectionalLight.fx`); masked materials now cast cut-out sun shadows (`DrawLinearDepthAlpha`). Built-in model `Assets.Tree` (`Content/GameObjects/Tree/`, Bark + Leaves parts with `TreeBarkMaterial`/`TreeLeavesMaterial`, generated by `Source/generate_tree.py`); Anvil GameObject > Nature > Tree adds it with the component. Sample: `Content/Scenes/FoliageTest.obsc`; see `Docs/markdown/Foliage_Wind.md`.
- `Engine/Voxels/` - voxel world from `EnvironmentSettings.Voxels`/`Voxel*` (Anvil viewport toolbar > World > Voxel World): `VoxelWorld` (byte grid of `VoxelBlock`s in 32³ chunks, centred on X/Y = 0, floor at `VoxelBaseHeight`; `SetBlock`/`FillSphere`/DDA `Raycast`; bottom layer not editable), `VoxelGenerator` (Flat/Hills/Mountains/Islands + caves, trees, sand shores, seeded `VoxelNoise`), `VoxelMesher` (greedy meshing per surface, coarser collision mesh, clockwise-from-outside winding), `VoxelTextures` (painted pixel-art albedo + normal maps; `VoxelSurfaceStyle`: everything but the Lamp is Wet Surface), `VoxelSystem` (`MainSceneLogic.Voxels`: synced in `UpdatePhysics` before the step; builds on a worker thread in Edit and synchronously in Play; registers chunk `ModelMeshPart`s in the `MeshMaterialLibrary` with ID 0 and adds one BEPU static mesh per chunk; remeshes edited chunks; `Reset` on scene swap; regenerates an edited world on Stop; draws the sea as a unit quad through the water pass). Scripts: `ScriptBehaviour.Voxels`. Sample: `Content/Scenes/VoxelTest.obsc` + `Content/Scripts/VoxelTestScript.cs` + `UI/VoxelTest`; see `Docs/markdown/Voxel_World.md`.
- `Engine/Particles/` + `Engine/Components/ParticleSystemComponent.cs` + `Engine/Renderer/RenderModules/ParticleRenderModule.cs` + `Content/Shaders/Forward/Particles.fx` - Unity-style particle systems (type id `particles`): module settings in `ParticleModules` (Main, Emission/Bursts, Shape, Velocity/Limit/Force, External Forces = scene wind, Noise, Color/Size/Rotation over Lifetime, Collision Plane/World, Texture Sheet, Sub Emitters by gameobject name, Renderer), CPU `ParticleSimulation` (GPU-free), procedural `ParticleTextures`. Play On Awake systems also preview in Edit (`MainSceneLogic.Update` -> `UpdatePreviews`); in Play the marker mesh is hidden via `TransformMatrix.Hidden`. Drawn as instanced quads after water, before weather, occluded/softened by the linear G-buffer depth. Script API `Play/Stop/Pause/Restart/Emit/EmitAt`. Sample: `Content/Scenes/ParticleTest.obsc` + `Content/Scripts/ParticleTestScript.cs` + `UI/ParticleTest`; see `Docs/markdown/Particle_Systems.md`. The **Volumetric** module draws a system as a raymarched volume (`Engine/Particles/ParticleVolume.cs`, `Volume` technique in `Particles.fx`): Source **Particles** splats each particle into a density grid, Source **Voxels** is a Counter-Strike 2 smoke that floods a voxel grid from the emitter (Volume m³, never through Static colliders, sun rays per voxel), holds for Duration and fades. `CarveTunnel/CarveHole` (bullets, HE) and `Opacity`/static `VolumeOpacity` (NPC sight uses it). Sample: `Content/Scenes/SmokeTest.obsc` + `Content/Scripts/SmokeTestScript.cs` + `UI/SmokeTest`. The **Lights** module (`ParticleLightsModule`, `Engine/Particles/ParticleLights.cs`) makes a system light the scene: one flickering System light at the particles' glowing centre (fades with them; optional shadows) or Per Particle lights on the brightest carriers. They are engine-owned `PointLight`s, never in `Scene.PointLights`: `Renderer.Draw` appends them (`ParticleSystemComponent.CollectLights`) to a per-frame copy of the scene's point lights for every lighting pass, while editor picking/icons use the scene list. Lit particles take the 4 strongest point lights. Built-in **FlameSheet** texture: a 4 x 4 flipbook of a flame tongue coloured by temperature (the ParticleTest campfire). **FireballSheet**: a 4 x 4 flipbook of an explosion billow cooling from white-hot to soot, drawn with Alpha blend + Brightness so the soot occludes (the ParticleTest explosion).
- `Engine/Physics/ScenePhysics.cs` + `PhysicsContact.cs` - BEPU bodies per gameobject, raycasts, and collision/trigger Enter/Stay/Exit events dispatched to Script Behaviours (`OnCollisionEnter`, `OnTriggerEnter`, ...). `Engine/Components/InteractableComponent.cs` + `ScriptBehaviour.FindInteractable/Interact/CameraRay` - raycast interaction. Sample: `Content/Scenes/CollisionTest.obsc` (first-person player `Content/Scripts/CollisionTestPlayerScript.cs` + station scripts); see `Docs/markdown/Collisions_and_Interaction.md`.
- Volumetric fog / god rays (`Content/Shaders/Deferred/Froxel.fx`, `FroxelRenderModule`, composed in `DeferredCompose.fx`): saved per scene in `EnvironmentSettings.Fog*` + `MaxAutoExposure` (Anvil Inspector > Environment > Volumetric Fog), copied into `GameSettings.g_Froxel*` each frame by `Renderer.ApplySceneFog` (Post Processing keeps only Enable/History). Slices are logarithmic in view Z; each frame: injection (rgb = source/m, a = extinction/m; sun, the 8 strongest lights from `FroxelRenderModule.RankPointLights`, baked probe L0 × `FogIndirectScatter`) → temporal resolve reprojected into last frame's grid (dropped on cuts/FOV/setting/scene/bake changes) → exact segment seed + 7 prefix-scan passes (prefix alpha = optical depth, half-float precision) → `DeferredCompose` `SampleFroxelFog` adds the partial slice in front of each pixel. Transparents drawn after compose are not fogged. Density ramps from `FogNearDensity` at `FogStartDistance` (30 m) to full at `FogFullDistance`; sky pixels keep fog up to `FogSkyShaftDistance` whole. `Engine/Components/FogVolumeComponent.cs` (type id `fog-volume`) adds density inside the gameobject's box without the ramp (dusty rooms; mesh hidden, max 8). Shafts only exist within the sun's cascades (Shadow Distance from the camera). Sample: the hall and the attic of `Content/Scenes/GodRayTest.obsc`; see `Docs/markdown/Scene_Lighting_and_Fog.md`.
- `Engine/Logic/Weather.cs` + `Engine/Renderer/RenderModules/WeatherRenderModule.cs` + `Content/Shaders/Forward/Weather.fx` - scene weather (rain, sandstorm, snow) from `EnvironmentSettings.Weather`/`WeatherIntensity`/`WeatherHaze`/`WindSpeed`/`WindDirection`: GPU particles in a camera-wrapped box plus a depth haze, drawn after water. A ground mist (`GroundFog` technique; `EnvironmentSettings.GroundFog`/`GroundFogHeight`/`GroundFogBase`, eased in `SurfaceWetness.GroundFog`, lingers after the weather) and raindrops on surfaces (`ApplyRainDrops` in `Gbuffer.fx`, every material with `MaterialComponent.RainDrops` except Wet Surface; `EnvironmentSettings.SurfaceDrops`, `SurfaceWetness.Drops`). Per-type look is `WeatherProfile`. Scripts use `ScriptBehaviour.SceneEnvironment`; PlayMode restores the environment on Stop. Sample: `Content/Scenes/WeatherTest.obsc` + `Content/Scripts/WeatherTestScript.cs`; see `Docs/markdown/Weather.md`.
- Wet Surface material type (`MaterialEffect.MaterialTypes.WetSurface` = 7, Inspector > Material > Shader > WetSurface): soaked albedo/roughness, world-space puddles that fill texture cavities (Displacement map = height, no parallax) and raindrop ripples, all in `ApplyWetSurface` in `Content/Shaders/GBufferSetup/Gbuffer.fx`. Rain drives it through `SurfaceWetness` (`Engine/Logic/Weather.cs`, eased by the renderer; `WeatherProfile.SurfaceWetness`/`PuddleRipples`). Wet pixels write material type 7 (normal target blue channel) so `DeferredEnvironmentMap.fx` uses a view-dependent fresnel for them (albedo alpha = material AO). Materials also have UV `TilingU/V`. CC0 ground textures: `Content/GameObjects/Textures/Ground/`. Sample: the Ground/Street/Plaza of `Content/Scenes/WeatherTest.obsc`; see `Docs/markdown/Material_Component.md`.
- Water (`GameObjectRole.Water` + Water material): `Engine/Physics/WaterVolume.cs` (footprint + wave surface), `Buoyancy.cs`, and water contacts in `ScenePhysics.UpdateWaterContacts` (every Dynamic body whose collider bottom crosses the surface, 5 cm exit margin) -> `WaterContact`, events `ScenePhysics.WaterEntered/WaterExited`, script hooks `OnWaterEnter/OnWaterExit`, `IsInWater`, `RaycastWater`. `Engine/Particles/WaterSplashes.cs` (`MainSceneLogic.WaterSplashes`): entries >= 1.2 m/s throw a crown/jet/spray from a pool of 12 engine-owned particle systems (no gameobject; drawn via `ParticleRenderModule.Draw(..., extraSystems)`, droplets die on a per-splash plane at the water), and every entry/exit leaves a ring (max 16, 4 s) that `Water.fx` (`SplashRings`) draws with foam; rain adds raindrop rings (`RainRings`, from `SurfaceWetness.Ripples`). Script API `Splash(point, speed, radius)`, `WaterSplashes`. Sample: `Content/Scenes/WaterTest.obsc` (pool + wave tank in rain) + `Content/Scripts/WaterTestScript.cs` + `UI/WaterTest`; see `Docs/markdown/Water.md`.
- `Engine/Recources/MaterialAsset.cs` - material assets: `.mat` JSON files in Content (default `Content/Materials`, `{ Version, Material }` = a `MaterialComponent`'s surface incl. the six texture slots; shipped by `Engine.csproj`). Gameobjects use one through `MaterialComponent.MaterialPath` (a copy of the values, saved as fallback); `MaterialAsset.SyncScene` (every frame in `MainSceneLogic.Update`) re-copies when the file changes, `SaveFrom` writes a linked component's edits back, `Capture`/`CreateFrom` save what a gameobject shows (model textures traced to Content files via `Texture2D.Name`, `TexturePathOf`), `Assign(entity, "Brick")`/`MaterialComponent.Link` link. Anvil: Assets > Create Material, click a `.mat` = asset Inspector (`MaterialAssetViewModel`, shares the `MaterialSurfaceTemplate` with the Material component), drag onto a Hierarchy row / double-click to assign, Material component Asset slot (Edit Asset/Unlink/Save as Material Asset), GameObject > Create Material from Selection. See `Docs/markdown/Material_Component.md`.
- `Engine/Logic/PersistentGameObjects.cs` - persistent gameobjects (`BasicEntity.Persistent`, saved / Inspector > Persistent, or `ScriptBehaviour.DontDestroyOnLoad()`): on `GameFlow.LoadScene` during Play they move into the new scene still running (scripts, bodies, HUD layers they opened); the new scene's own copy is left out; Anvil's Stop returns them to the edited scene.
